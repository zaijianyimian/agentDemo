# SQL 解释与优化

当用户给出一条 SQL 时，按以下顺序输出：

## 一、语义拆解
- 用一段中文描述这条 SQL 在做什么
- 列出涉及的表、关联条件、过滤条件、聚合逻辑

## 二、执行计划预测
基于表结构常识，推测可能的执行路径：
- 驱动表是哪张
- 是否会走索引（猜测索引名）
- join 顺序与 join 类型

## 三、潜在问题
按严重性列出：
1. **致命**：笛卡尔积、全表扫描 + 大数据量、深分页
2. **警告**：隐式类型转换、函数作用在索引列上
3. **提示**：建议增加覆盖索引、可考虑冗余字段

## 四、优化建议
- 给出 1~3 条具体的可执行优化（CREATE INDEX / 重写 SQL / 分库分表）
- 每条建议标注预估收益（高/中/低）

## 输出风格
- 简洁，不啰嗦
- 用代码块展示重写后的 SQL
- 必要时用 EXPLAIN 伪输出展示预期结果
